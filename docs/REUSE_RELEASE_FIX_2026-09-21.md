# 上线前方案复用入口修复

## 发现

已有方案界面原先仅提供“重新生成”，绑定 generate(true)，发送 forceRegenerate: true。用户想检查是否需要更新时也只能强制重新生成。服务端本身已有安全复用路径，测试证明可以复用；先前 c261d900 日志没有记录是否强制生成或旧方案是否存在，不能据此还原那次点击。

## 修改

- 已有方案的常用操作改为“检查并更新”，发送普通生成请求，先检查当前状态是否允许复用。
- 保留独立的“完整重新生成”入口，只有该入口显式绕过复用；界面提示其等待更久。
- 增加生产环境可用的 reuse_decision 日志，只含随机请求标识、动作和原因代码。记录 NO_EXISTING_ROUTINE、EXPLICIT_FORCE_REGENERATION、早期校验原因、完整上下文是否相同及最终是否重算；不记录个人资料、提示词或记忆正文。
- 没有放宽皮肤、产品可用性、知识、安全、使用反馈等已有复用检查。

## 验证

- 263 项方案、安全、今日展示和方案 API 测试通过。
- 扩展真实服务测试：重复请求返回完全相同的方案及解释，回调为 reused；方案模型、解释模型、写入各保持一次；显式完整生成才再次调用模型，并记录强制生成原因。
- 已有测试继续覆盖皮肤护理需求变化、数量为零、禁用成分等情况下不复用。
- 相关文件 ESLint 和生产构建通过。

复用仍要查询并校验最新数据，不能承诺瞬时返回。首次生成、旧方案缺少可验证上下文或当前条件需要调整时仍可能调用模型。未部署，未在真实登录浏览器中做交互验收；上一轮已知全库样式测试及 lint 遗留问题不在此修复范围内。
