## 上线前必须处理

### 1. 正式访问地址与登录

本地 `NEXT_PUBLIC_APP_URL` 指向 localhost。发布时必须设置正式 HTTPS 地址，并核对 Supabase Site URL、允许的 `/auth/callback` 回调、邮件发送与实际登录。不要把本地 `.env.local` 原样当作生产配置。

`AUTH_ALLOWED_EMAIL` 当前非空，只有指定邮箱可以使用。招聘方拿到链接不等于可以体验功能。建议简历链接先提供隔离的演示数据入口，个人真实数据仍要求登录；此演示入口尚未实现。若开放注册，必须先验收双用户隔离并设置模型调用额度。

### 2. 生产记忆与功能预期

`createConfiguredOpenVikingClient` 明确禁止 production 使用 single_user_dev。原因是固定凭据不构成 Beauty OS 多用户隔离边界。不能为了获得开发环境同样的记忆效果直接删除保护。

方案仍可利用数据库中的档案、皮肤、库存和使用反馈，但开发环境额外注入的 OpenViking 记忆在生产中不会启用。上线说明不能声称已完成多用户长期学习闭环。若产品要求该功能，需先实现并验收用户隔离的记忆服务。

### 3. 真实数据验收

在专用测试用户上依次执行：登录、档案保存、资产录入与图片、数量修改、皮肤记录、AM/PM 生成与复用、反馈保存、刷新重进、退出再登录。重点检查：

- 用户 A/B 无法互读互改个人数据，普通用户无法访问管理员操作。
- 当前迁移全部应用；方案、反馈原子 RPC 与代码版本匹配。
- 私有图片桶权限、文件大小和格式限制、签名链接过期行为正确。
- 条件不变时返回原方案及解释、不再调用模型；条件变更、产品耗尽、禁用成分更新时按原规则重新检查。
- 网络中断、重复提交、模型失败时不丢数据、不重复记录消耗、不把未保存结果报成成功。

仓库部分 live RLS 测试会改写测试账户档案，不应对真实个人账户直接运行。`output/release-readonly-probe.py` 是本次只读探针，不打印凭据，结果写入 `output/release-live-rls-readonly.json`。

### 4. 长请求与费用控制

现有实测样本约 60.5 秒，其中两次模型调用约占 80%。代码中 Planner 超时预算 75 秒、解释模型默认预算 30 秒，另有数据读取和保存。因此必须验证托管平台的请求时长、网关超时和后台任务生命周期，不能按普通短接口部署后假定生成能完成。

普通检查已允许复用；“完整重新生成”仍会产生完整模型请求。未发现生成路由的服务端速率限制/额度控制。客户端按钮禁用不能代替服务端限流；公开开放注册前应配置按用户的额度、并发与费用告警。此轮未擅自改变用户可用次数。

### 5. 运维与回滚

正式平台、域名、HTTPS、环境变量、数据库备份、迁移执行记录、模型额度、日志监控和回滚版本均待确定。工作区有大量既有未提交变更，发布前需要形成可追溯的发布版本，不应直接把当前混合工作区当作已审阅版本发布。

## 本轮已修复

- 修正两项已过期的样式断言：当前背景使用统一遮罩变量，首页输入框使用一行起步的自适应高度。保留现有产品样式，不通过改页面来迎合旧断言。
- ESLint 排除已安装的 `.agents`/`.codex` 工具目录，不更改业务源码检查规则。工具目录噪声排除后仍保留 15 个真实项目错误可见。
- README 增加当前发布状态，将“未接入 AI”等旧 v0.3 内容明确收纳为历史说明，避免上线文档误导。

## 剩余 lint 分类

- 2 个业务组件错误：资产页的 props→state 同步，以及反馈对话从 sessionStorage 恢复状态的 effect。反馈页另有依赖警告。需要结合真实交互检查状态恢复和切换，不能仅为消除 lint 随意改动。
- 13 个测试类型错误：知识与证据测试使用 `any` 夹具。属于测试可维护性问题，未导致本次测试失败。
- 其余警告包括图片元素及未使用变量。没有为消除图片警告压缩或降低图片质量。

## 微信小程序

当前验收对象是 Next.js WebApp；本仓库没有完成小程序前端、账号与发布配置。Web 版通过后，小程序仍需单独验收登录、接口、网络配置、图片上传、导航、隐私说明和真机体验。不能把 Web 构建成功当作小程序已可发布。
